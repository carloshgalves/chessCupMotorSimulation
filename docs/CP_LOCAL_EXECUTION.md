# Local calibration and evidence cutover

Use the consolidated branch. Never cancel a run before downloading and verifying its published artifacts. `bash scripts/cp-local.sh sync` downloads exact artifact IDs, checks SHA-256 and writes a local archive manifest; it also refreshes the frozen inventory with later artifacts, including abandoned Elo research (not used for CP). A published inventory is a catalog, not a copy of ZIP bytes. Do not commit raw corpora, archives, or local reports automatically.

`bash scripts/cp-local.sh build` validates the exact binary hashes. Different compiler builds or package revisions may fail; do not bypass the hash gate. `bash scripts/cp-local.sh start 2 4` starts two workers with four CPU quota and 8 GiB total memory. `cpu 2` changes quota live. `pause` / `resume` freeze running processes without saving RAM to disk. `stop` creates a shared stop marker and waits for each worker to finish its current complete position and atomically save; normal stage completion also persists. Wait for the container to exit before powering off. A sudden power loss can lose the current unsaved stage. Linux suspend freezes computation; resume usually continues but network/UCI failures can occur, so use cooperative stop before suspending. No per-position disk writes. Restart with `start` after shutdown; completed stages and prefix rows are verified and reused. Prior FIT selection is pinned per player. If source/profile/engine mismatch occurs the player is blocked instead of silently re-running. Inspect FAILED markers/logs; remove a marker only after diagnosing a technical failure.

Only two development passes, no TEST-driven refinement. Reuse coarse FIT artifact with exact source, positions, profile and engine binding; first compare baseline + five finalists in TUNE. If neither panel meets ±1, allow one bounded fine search (max 12 new recipes). Measure the locked candidate once on diagnostic reserved data. No automatic repeat when the target fails. Existing cloud recovery reports are preserved instead of repeating. Five retained baselines are excluded. A new independent holdout is needed for strict qualification; no automatic activation or claim that ±1 is achievable for every player.

Before local start, create empty files in results/exclude for players whose cloud recovery jobs you intend to let finish; sync again after they finish. A queued GitHub matrix cannot be paused/migrated midway; only uploaded artifacts can be resumed locally. Do not cancel all runs; prioritize saving obsolete duplicates and remaining useful shards. Review legacy failures offline using `bash scripts/cp-local.sh review PLAYER RUN`, which replays ZIP evidence without rerunning matches. Heavy workflows are manual-only on the consolidated branch; original PR runs remain unchanged.

TUNE is prioritized from its original arm and supplemented only with unused development FIT trajectories when necessary, excluding all FIT-panel and TEST games and FENs. Structural support below 12 per phase stops before expensive measurement. Downloaded FIT choices are pinned by artifact ID. A completed old cloud recovery is retained as evidence rather than automatically repeated.

The local executor now prioritizes the strict FIT artifact (including verified refinement) over the older coarse artifact. If refinement already occurred, no additional fine search is permitted; only development comparison and, if eligible, reserved diagnostic are run. If FIT/TUNE do not meet the target, the reserved rerun is skipped. The prior observed reserved report remains in the archive. The two-pass budget includes reused strict refinement. Cloud plan refreshes the four/current in-flight recovery exclusions and refuses normal local start while the cloud recovery queue can start competing jobs; use an explicit overlap override only if acceptable, or wait for the active jobs to finish, sync, cancel that one run, sync and start. It does not cancel any workflow automatically.
